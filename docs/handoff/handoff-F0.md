### 2. Angular scaffold in the existing folder
- First check the available options with `ng new --help` (CLI 21).
- Generate the project **in this folder** (`--directory .`), name `j-training`: SCSS, routing, no SSR, zoneless,
  without initialising git (done in step 4).

### 3. Code quality
- angular-eslint (`ng add @angular-eslint/schematics`), Prettier with consistent `.prettierrc` and `.editorconfig`.
- npm scripts: `lint`, `format`, `format:check`, `test:ci` (no watch), `build:prod`.
- `ChangeDetectionStrategy.OnPush` on the root component; remove the demo page generated by the CLI.
- README.md with: description, stack, commands, link to `docs/`.

### 4. Git and GitHub
- `git init` with initial branch `master`, a proper `.gitignore`, first commit `chore: scaffold Angular 21 project`.
- A versioned script `scripts/setup-github.ps1` that, through `gh`:
  - creates the public repository `j-training` and pushes `master`;
  - creates `dev` from `master` and makes it the default branch;
  - allows only squash merges and merge commits (rebase disabled) and deletes branches after merging;
  - creates a ruleset for `master` and one for `dev`: mandatory PR, 0 approvals, force push and deletion blocked;
  - enables GitHub Pages with "GitHub Actions" as the source.
- Show the script to Gianluca and get his confirmation before running it.

### 5. CI and deploy (branch `feature/f0-ci`)
- `.github/workflows/ci.yml`: on PRs to `dev` and `master` → `npm ci`, lint, format:check, test:ci, build.
- `.github/workflows/deploy.yml`: on push to `master` → production build with `--base-href /j-training/`,
  `index.html` copied to `404.html`, `actions/upload-pages-artifact` and `actions/deploy-pages`.
- Use the current versions of the official actions (check them, do not go by memory).
- After the first green run, add the CI check as a required status check in the rulesets.

### 6. First release

- Check the deploy at the Pages URL from desktop and phone.
