## Decisions (and why)
- **Project conventions in the lint**: a convention written only in documents erodes, a lint rule is enforced by
  CI on every PR. Cost: a few false positives to handle case by case.
- **angular-eslint 21, not 22**: 22 is aligned with Angular 22; the project stays on Angular 21 because of PrimeNG 21.
- **LF enforced by `.gitattributes`, `.editorconfig` and Prettier**: same files on Windows and on the Linux CI,
  no phantom diffs.
- **`docs/` excluded from Prettier**: hand-written documents, formatting is up to the author.
- **Merge method enforced by the ruleset** (`allowed_merge_methods`), not only by the repository settings:
  the branching strategy does not depend on the button chosen. Squash with the PR title and body:
  the Conventional Commit title of the PR becomes the commit on `dev`.
- **Idempotent, versioned `gh` script**: the repository configuration is code, reproducible and re-runnable
  (e.g. `-RequiredStatusChecks 'ci'` after the first green run).
- **`github-pages` environment from `master` only**: when Pages is enabled, GitHub authorises the default branch
  (`dev`); removed for least privilege on the production environment.
- **`.nvmrc`** as the single source of the Node version, for local development and CI.
- **App name as a constant in the root component**: it is a proper name, not text to translate.
  Every other UI text goes through Transloco from F1 on.
